# 使用与完善操作手册（保藏批件申请方向）

本手册面向"把 hgr-compliance-tool 用起来，并补上保藏批件申报内容"的实际操作。
基线版本：RULESET_VERSION 2.0.0，规则库审阅日 2026-11-11（已按国家卫健委令第 16 号完成换版）。
> 注：原"尚未覆盖：申请材料清单"缺口已在 v2.0.0 补齐——新规第 17/22/26/27/36 条把采集、保藏、国际合作、备案、出境的材料清单全部入法，工具已逐项落地。逐条映射见 `docs/换版条号映射-16号令.md`。

### 使用流程（终端用户在浏览器里做的）

1. 选入口：企业合规/注册（完整评估）或研究者/BD（快速判断）。
2. 新项目申报评估：四层决策漏斗——身份识别 → 资源识别 → 活动识别 → 触发与豁免。
3. 已获批项目管理：变更 / 延续 / 报告评估，先选事项类型（保藏、采集、国际合作等）。
4. 逐题作答；所有可见题答完才出现"生成评估报告"。
5. 看报告：结论 + 条款引用 + 置信度分级（A 法规 / B 主管部门口径 / C 实践惯例）+ 义务时限 + 罚则。
6. 浏览器端导出 Word（.docx），含回答摘要表，可留痕归档。

## 二、当前能力边界（保藏批件方向）

已覆盖（v2.0.0 / 2026 版细则第 16 号令）：
- 是否构成保藏（第 21 条"仅用于科学研究"，三类排除：临床诊疗教学为主兼顾科研、已上市药械生产目的、临时存储）
- 是否需要保藏行政许可（条例第 14 条；细则第 21、22 条，新增"符合保藏技术规范"）
- 采集被吸收（第 20 条，扩展至国际合作）
- **保藏申请材料清单 8 项**（细则第 22 条，v2.0.0 新补）
- 保藏许可例行义务：年度报告（1 月 31 日前，内容改为保藏/使用/开放共享/成果 4 项，第 24 条）、重大事项变更（申请单位/场所/目的/方案，第 23 条）、许可延续（届满 30 个工作日前，第 51 条，有效期按申请确定）、台账与来源使用记录（第 10、24 条）、开放共享（第 24 条）
- 外方单位禁止保藏（条例第 7 条、细则第 9 条）、罚则（条例第 36、40、41 条）

尚未覆盖（进一步完善的方向）：
- 主管部门审批办理时限（新规第 46 条规定一般许可 20 个工作日、可延 10 日；紧急审批 5 个工作日第 52 条——尚未作为义务项展示）
- 受理、补正、撤回、撤销等程序性节点（细则第 45、49、50 条）
- 监督检查与重点检查对象（第 54–56 条）的主动提示
- 申报材料模板 / 示范文本（须以国家卫健委服务指南最新文本为准）

历史说明：v1.6.0 的"材料清单补全"补的是**样本类型识别清单**（哪些样本受监管），不是申报材料清单；申报材料清单在 v2.0.0 依据新版细则第 17/22/26/27/36 条补齐。

## 三、如何完善（改代码的位置与方法）

规则引擎与 UI 完全解耦，纯 TypeScript 数据 + 函数，核心资产都在 `src/rules/`。

### 文件分工

| 文件 | 作用 | 改它来做 |
|---|---|---|
| `src/rules/types.ts` | 类型定义：Confidence、Citation、Obligation、Conclusion、Question、Answers、GrayArea | 新增结论类型或字段时 |
| `src/rules/questions.ts` | 题库（四层决策漏斗 + 变更题组）、推导函数 | 增/改题目、选项、触发条件 when、阈值 |
| `src/rules/evaluate.ts` | 评估器：答案 → 结论/义务/风险/灰色地带 | 增/改结论、义务时限、条款引用、罚则 |
| `src/rules/regulations.ts` | 法规元数据、RULESET_VERSION、审阅日 | 新增依据法规、升级版本号 |
| `src/rules/glossary.ts` | 术语表 | 补充术语解释 |
| `src/utils/exportDocx.ts` | Word 导出 | 调整报告导出格式 |
| `smoke-test.mts` | 规则冒烟测试 | 新增回归用例 |
| `docs/RULES.md` | 规则说明 | 同步记录改动 |

### 举例：补"保藏批件申请材料清单"

核心结论在 `src/rules/evaluate.ts` 的 `bank-approval` 分支（搜索 `id: 'bank-approval'`）。它是一个 `push({...})` 对象，字段包括 id/type/title/summary/citations/obligations/reasons/risk。

做法：在该结论里追加一个 `obligations` 条目，或在 `citations` 后新增说明字段，例如：

```
{ title: '申请材料清单',
  deadline: '【依据卫健委服务指南填写，逐项列明】',
  citations: [X('第二十九条'), F('服务指南：保藏许可申请材料')] }
```

其中 `A()` = 行政法规（条例）、`X()` = 实施细则、`F()` = 常见问题解答口径、`F25s()` = 2025 年问题解答。置信度 A/B/C 已封装在这些函数里，不用手写。

### 改完必做的三步闭环

1. `npm run test:rules` —— 50+ 条用例必须全绿，新行为要新增用例（命名延续 A32、A33…）。
2. `npm run build` —— 类型检查 + 构建通过。
3. 浏览器实测：在 http://127.0.0.1:3000 走一遍保藏路径，确认报告输出正确，再导出 Word 检查版式。

### 法规依据的分级规范（重要，别踩坑）

| 级别 | 来源 | 现在的封装 |
|---|---|---|
| A | 《人类遗传资源管理条例》（2024 修订） | `A('第十四条')` |
| A | 《人类遗传资源管理条例实施细则》（2023） | `X('第二十八条')` |
| B | 《人类遗传资源管理常见问题解答》（2023.09）等主管部门解答口径 | `F('...')` |
| C | 申报实践惯例 | 备注说明 |

原则：
- 每条结论可溯源到具体条款，不要把 FAQ 口径（B）写成法规条文（A）。
- 受理机关统一表述：2023 年机构改革后职责由科技部划转国家卫健委，以国家卫健委政务服务平台现行口径为准。
- 规则覆盖不到的灰色地带（如单位股权结构不明）标记转人工，不给推测性结论。
- 订正或补充规则时请附条款依据；真实案例回归请脱敏。
- 本工具输出为基于公开法规的初步评估，不构成法律意见。
